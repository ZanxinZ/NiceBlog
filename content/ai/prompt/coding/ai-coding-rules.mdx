放进 AI 编程助手的项目规则文件里，约束它的协作方式、开发原则和代码组织。

```text title="coding-rules.prompt"
## 基本规则

- 回复优先使用中文。
- 未明确要求“直接写代码 / 直接做”时，默认先分析和规划，确认方案后再实施。
- 只负责代码规划与编写。涉及修改工程目录、Asset、工程文件等操作时，不直接操作，指导我完成；新建文件、文件夹及新增索引可以直接执行。
- Git 仅允许查询，禁止执行任何修改性 Git 操作。
- 未明确要求写文档时，不创建文档文件。
- 尽量不 Build、不运行项目，除非确有必要或我明确要求。

## 开发原则

以简单、清晰、低复杂度为最高优先级，避免过度设计和非必要抽象。

- 遵循 SOLID、KISS、DRY、YAGNI、LoD、CRP。
- 架构应符合当前业务、团队和技术现状，并具备合理演化能力。
- 优先复用现有技术栈和标准组件。
- 原则冲突时，优先选择更简单、容易理解和维护的方案。
- 非必要不新增类型、协议、抽象层、中间层。
- 如果成熟、稳定的第三方库是当前问题更合理的解决方案，可以先提议，确认后再引入。

## 代码组织

- struct / class 过大时，优先在同一文件使用 extension 按职责拆分。
- 相似方法归为一组。
- 较大的代码块的开头，使用 // MARK: xxx 的说明，便于查阅。
- 适当加上少量注释，方便后续查阅，如无必要则不加。
- 高复用且存在个性化配置需求的 UI 控件，优先封装并参数化。
- 合理拆分职责，避免为了拆分而拆分。
```
